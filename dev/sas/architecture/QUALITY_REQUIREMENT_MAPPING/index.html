    Quality Requirement Mapping¶

    The SRS scenarios map to implementation tactics and executable fitness functions. Every scenario has the status Pass in the NFR traceability matrix.

    Quality attribute scenario Architectural response UMTAS realisation Fitness function and evidence
    NFR-Corr-1 Canonical parser contract and reviewed UP fixtures. Parser output is validated against the canonical contract and compared with version-controlled ground-truth fixtures. Test 100% field precision and recall, with zero omitted or invented values; see evidence.
    NFR-Corr-2 Two solver engines and independent hard constraint validation. The CP-SAT and genetic engines both return results that the regression suite validates independently against the hard constraints. Test 100% of conflict-free results pass independent validation, with zero overlaps; see evidence.
    NFR-Sec-1 Role scoped administration and aggregate analytics boundary. GET /analytics/module-demand is restricted to the uni_admin role and returns module enrolment counts only, with no student identifiers or individual schedules. Cohorts below five students are withheld (returned as null). Test zero linkable student identifiers, individual schedules or reconstructed identities; see evidence and boundary unit tests.
    NFR-Scale-1 Persisted jobs, BullMQ queues and separate workers. Job records are persisted, jobs are queued in BullMQ, and separate workers process them. Test 100 concurrent users for at least five minutes, 99% success for well-formed submission and status requests and p95 at most 2 s; see evidence.
    NFR-Perf-1 Asynchronous acceptance and status polling. Submission returns HTTP 202 with a job identifier, and clients poll the status endpoint. Test submission and status p95 at most 2 s, with at least 99% success; see evidence.
    NFR-Perf-2 Scoped indexed reads. Student read endpoints return collections scoped by university, module or the caller's own records. Test every student read p95 at most 1 s, mean at most 500 ms and 100% success; see evidence.
    NFR-Cap-1 Stateless API and connection pooling. A stateless API serves requests through a pooled PostgreSQL connection of up to 50 connections. Test at least 50 requests/s for five minutes, 99% success and aggregate p95 below 1 s; see evidence.
    NFR-Eff-1 Worker processing duration instrumentation. The solver and parser workers log SOLVER_PROCESSING_DURATION (msPerEvent) and PDF_PARSER_PROCESSING_DURATION (msPerKb) entries. Test solver p95 at most 500 ms per event and parser p95 at most 300 ms per KB; see evidence.
    NFR-Eff-2 Persist then enqueue before HTTP 202. The submission endpoint persists the job record and enqueues the job before it returns HTTP 202 with the job identifier. Test job acceptance p95 at most 1 s, with 100% valid submissions accepted; see evidence.
    NFR-Rely-1 Dedicated session canary under sustained load. A session check request runs alongside the load profile for the full soak duration. Test session canary success at least 99% throughout the sustained soak; see evidence.
    NFR-Rely-2 Three step account and session establishment. Account creation, email sign-in and university selection establish a university-scoped session. Test 100% sign-in completion and p95 at most 1 s per step; see evidence.
    NFR-Avail-1 Public health monitoring. An external UptimeRobot monitor checks the public endpoint. Test at least 99.5% public uptime across the 30 day release window; see evidence.
    NFR-Sec-2 CSP, clickjacking protection and authenticated scanning. The API sends a Content Security Policy with default-src 'none' and frame-ancestors 'none', X-Frame-Options: DENY and X-Content-Type-Options: nosniff. The frontend sends a nonce based Content Security Policy that includes frame-ancestors 'none'. Test zero Medium or High ZAP alerts in baseline and authenticated scans; see evidence.
    NFR-Sec-3 Dependency audit gate. pnpm audit --audit-level=moderate --prod gates production dependencies. Test zero moderate or higher production dependency findings; see evidence.
    NFR-Por-1 Playwright browser projects. The end-to-end suite defines Chromium, Firefox and Microsoft Edge projects. Test zero failures across Chromium, Firefox and Microsoft Edge; see Chromium, Firefox and Edge.
    NFR-Acc-1 Page by page Lighthouse audit. Each audited page is scored on the Lighthouse accessibility category. Test accessibility score above 90 on each audited page; see evidence.
    NFR-Maint-1 Parser adapter contract and controlled test adapter. The parser registry discovers every BasePDFParser subclass in the adapters package that declares an ADAPTER_KEY, so the synthetic adapter is selectable with no change outside the adapter directory. Test zero changed production components outside the university adapter layer; see evidence.
